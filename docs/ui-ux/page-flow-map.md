# Page Flow Map

每页 **ONE_JOB**。表格中的 Primary 是该页唯一主 CTA。

## 主 CTA 总表

| Page | 唯一任务 | Primary Action | Secondary | Back | Next |
| --- | --- | --- | --- | --- | --- |
| 工作台 | 回到未完成工作 | 继续处理（有任务时）/ 创建项目（空） | 查看全部项目 | — | 进入对应任务页 |
| 项目列表 | 选择或创建项目 | 打开当前项目 / 创建项目 | — | 工作台 | 项目概览 |
| 项目概览 | 看进度与下一步 | 继续（动态：下一真实任务） | 项目资料 | 项目列表 | 当前阶段页 |
| 账号定位 | 确认账号方向 | 确认定位并继续 | 重新生成；高级设置 | 项目概览 | 内容计划 |
| 内容计划 | 确认这一周做什么 | 确认内容计划（有 DRAFT 时）或 生成脚本（已确认时当前条） | 重新规划；查看参考依据；历史版本 | 账号定位 | 选题与脚本 |
| 选题与脚本 | 完成并确认一条脚本 | 确认脚本 | 需要修改；重新生成；历史版本 | 内容计划 | 视频制作（确认后） |
| 视频制作 | 审核并确认一条成片 | 未生成：开始制作视频；待审：确认最终成片 | 需要修改；下载（确认后） | 选题与脚本 | 发布与数据 |

| 作品详情 | 看这一条作品全链路 | 按缺口：登记 / 录入数据 / 查看复盘 | 技术详情 | 发布列表 | 数据或复盘 |

说明：AI 复盘页「采纳」是卡片级操作，页面不另设第三颗黑色主按钮。页级 Primary 在无待审建议时改为「查看下一轮会参考什么」或「返回内容计划」。

## 工作台

A. Continue Work：项目名 + 当前任务人话 + [继续处理]
B. Needs Attention：仅真实待办（待确认脚本 / 待审核视频 / 待发布 / 待录入 / 待审 AI 建议）。禁止 fake task。现有 `task-center` / `collectProjectTask` 只展示真实 facts。
C. Recent Projects：名 / 阶段 / 最后操作 / 下一步
D. Empty：创建项目后 AI 会依次帮助完成定位、规划、脚本和视频。成功后**直接进账号定位**，不甩回列表。

不要做成信息看板。现有 `WorkflowProgress` 全站阶段条降为概览次要或移入项目页。

## 项目概览

不复制工作台。展示：当前阶段、本周 7 条进度（计划/脚本/视频/已发布）、最近一条内容、下一步。项目资料 secondary。

## 账号定位

主区只：账号类型、目标用户、核心目标、内容风格。
高级折叠：行业、平台、补充要求、特殊限制。
来源标记：AI 已整理 / 已从项目资料复用 / 你填写。全部可编辑（UX-G11）。

## 内容计划（重点）

禁止默认展开 7 条全文。

顶部：本期 7 天 + LearningContextSummary（定位/用户/风格/已采纳 N 条）+ [查看参考依据]。
有 DRAFT 新版：主位置只放「有一份待确认的新规划」+ [确认新规划]，confirmed 旧版不得占主位。
Topic 默认：Day、title、一行摘要、标签、状态、一个 CTA（查看详情 或 生成脚本）。
详情用 Drawer，同时只开一条。
历史：`VersionHistoryDrawer` 默认折叠。

## 选题与脚本

队列 + 编辑器。队列：Day1 ✓ / Day2 ● / Day3 ○。
主区：标题、人话状态、时长与特殊要求、开头/正文/结尾/CTA/风格/备注。
动作：确认脚本、需要修改；secondary 重新生成、编辑、历史。
1024 宽：动作落到正文下方。禁止脚本正文独立纵向滚动。

## 视频

A 未生成：[开始制作视频]
B 生成中：`AsyncTaskProgressV1` 只反映真实阶段；允许离开页面。禁止 fake progress。
C 待审：左播放器（竖版限 max-height，横版仅在真实 landscape artifact 存在时切换）+ 右清单与 Human Review。
决策：[需要修改] [确认最终成片]。确认后：最终成片已确认 + 下载竖版 + 下一步发布。
下载文案只允许「已开始下载 / 请查看浏览器下载记录」，禁止「下载完成」。

## 发布与数据（连续 5 步）

1 下载成片（绑定 final accepted video）
2 抖音 App/网页发布 → [我已经发布] = USER_ASSERTED，禁止「平台已验证」
3 登记链接与标题 → 已登记 · 用户手动发布 · 未验证
4 数据：无则录入第一组；有则 summary
5 条件满足：[查看 AI 复盘]
不向用户解释 Publication 内部状态机。

## 数据录入 / 监控

字段：播放、点赞、评论、分享、收藏、新增粉丝、采集时间。两列 compact。允许 0；空=未填写；0=真实 0。
保存=追加历史，不覆盖。
监控默认当前表现 + 相对变化；2 条 snapshot 用轻量趋势；历史默认 3 条 + 查看全部。禁止两套重复表。

## AI复盘

去掉工程语言。摘要 → 观察 → 建议卡（默认最多 3 条，其余「查看另外 N 条」）。
操作后：保存中 → refetch → 显示 persisted status。
回流：已采纳 N 条仅作下一轮参考，不自动改定位/方向/目标/已确认计划。

## Onboarding

轻量 3 步：创建项目 → 定位 → 第一份计划。随时可退。无超级 wizard。

## 错误 / 空状态 / 异步

- `InlineActionErrorV1`：贴在刚才操作旁 + 重试；技术详情折叠。禁止远离按钮的顶部报错。
- 空状态必须带下一步动作。
- 长任务：`AsyncTaskProgressV1` + 可离开。超时沿用现有 recover/poll，不新造超时体系。
