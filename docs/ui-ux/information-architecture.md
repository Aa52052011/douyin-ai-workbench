# Information Architecture

## 1. 一级导航（全局，不承载生产步骤）

与现有 `GLOBAL_NAV_V2` 对齐，语义冻结：

| ID | 文案 | 路由 | 职责 |
| --- | --- | --- | --- |
| workbench | 工作台 | `/dashboard` | 跨项目任务中心：继续上次、待处理、最近项目 |
| projects | 项目 | `/dashboard/projects` | 项目列表 / 进入单个项目生产线 |
| publish-data | 发布与数据 | `/dashboard/monitoring` | **跨项目运营中心**：所有已登记作品、待录入、待复盘 |
| settings | 设置 | `/dashboard/settings` | 账号与工作区设置 |

一级导航**禁止**再放：账号定位、内容计划、脚本、视频、Agent 测试。

工程路由继续隐藏（已有 `LEGACY_NAV_HIDDEN_FROM_NORMAL_USER`）：

- `/dashboard/agents`
- `/dashboard/content-planning`
- `/dashboard/scripts`
- `/dashboard/videos`
- `/dashboard/assets`

## 2. 「发布与数据」双入口（必须区分，不得混用）

| 入口 | 范围 | 用户心理 | 默认落地 |
| --- | --- | --- | --- |
| 一级「发布与数据」 | 跨项目 | 「我所有要跟进的作品」 | `/dashboard/monitoring` 列表，按项目分组或最近活动 |
| 项目二级「发布与数据」 | 当前项目 | 「这条生产线怎么发、怎么记数据」 | `/dashboard/projects/:id/publish` 当前内容队列 |

规则：

- 从一级点进某条作品，进入**该项目上下文**的作品详情 / 数据 / 复盘，并显示项目侧栏。
- 从项目内点「查看全部作品」，可跳到一级运营中心并带 `projectId` 过滤。
- 文案不得都写成含糊的「监控」。一级用「全部作品与数据」，项目内用「本项目发布」。产品标签仍可简称「发布与数据」，副标题必须不同。

推荐副标题：

- 一级：`跟进所有已发布作品的数据和复盘`
- 项目内：`下载成片、登记抖音链接、录入数据`

## 3. 项目内二级流程（侧栏，仅 project context）

建议顺序与用户心理模型：

| 侧栏 | 路由 | 页面唯一任务 |
| --- | --- | --- |
| 项目概览 | `/dashboard/projects/:id` | 看清本项目进度与下一步 |
| 账号定位 | `.../positioning` | 确认账号方向 |
| 内容计划 | `.../content/plans` | 确认这一周做什么 |
| 选题与脚本 | `.../content/scripts` | 完成并确认一条脚本 |
| 视频制作 | `.../content/videos` | 审核并确认一条成片 |
| 发布与数据 | `.../publish` | 完成发布登记和数据回流 |
| AI复盘 | `.../performance` 或作品详情复盘 Tab | 理解表现并决定采纳哪些建议 |

**现状缺口：** `PROJECT_MAIN_NAV` 无独立「AI复盘」项（复盘在 monitoring 详情 / performance）。Phase A/G 将侧栏补上「AI复盘」，指向项目内复盘入口，不新造后端。

「项目资料」保持折叠 secondary（已有 `PROJECT_FOUNDATION_NAV`）：

产品信息 / 市场调研 / 市场分析 / 推广策略 / 素材库。

这些不是主线步骤，不得与主流程并列抢视觉。

## 4. 用户心理阶段 vs UI 页面

| 心理阶段 | UI 落点 | 合并策略 |
| --- | --- | --- |
| 1 账号定位 | 定位页 | 独立页 |
| 2 内容计划 | 计划页 | 独立页 |
| 3 选题与脚本 | 脚本页 | 独立页 |
| 4 视频制作 | 视频页状态 A/B | 与审核导出同页不同状态 |
| 5 审核与导出 | 视频页状态 C | 同页 |
| 6 手动发布 | 发布页 Step 1–3 | 同页连续步骤 |
| 7 数据监控 | 发布页 Step 4 或作品详情数据区 | 不另起「Publication 状态机」页 |
| 8 AI复盘 | 复盘页 / 作品详情复盘 | 独立主任务，不深藏 |

## 5. App Shell 线框（desktop）

```
┌─────────────────────────────────────────────────────────────┐
│ Logo  工作台  项目  发布与数据  设置     [项目切换器]  用户   │  紧凑顶栏
├────────────┬────────────────────────────────────────────────┤
│ 仅项目内   │  ProjectCompactHeader：名 · 抖音 · 当前阶段     │
│ 显示       │  [编辑项目]                                     │
│            ├────────────────────────────────────────────────┤
│ ✓ 定位     │  ← 上一步                                       │
│ ✓ 计划     │  页面标题                                       │
│ ● 脚本     │  一句话解释 · 当前状态          [唯一 Primary]   │
│ ○ 视频     │                                                │
│ ○ 发布     │  主内容（随页面滚动，禁止主卡片内嵌套滚动）        │
│ ○ 复盘     │                                                │
│            │  ───────────────────────────────────────────── │
│ 项目资料 ▸ │  ← 上一步                          下一步 →     │
└────────────┴────────────────────────────────────────────────┘
```

规则：

- 顶栏高度紧凑（沿用 `--acf-topbar-height`）。
- 左侧只在 project context 出现。
- 阶段：✓ 完成 / ● 进行中 / ○ 未开始。不用花哨图标，不做大量动画。
- 工作台 / 项目列表 / 设置 / 一级发布与数据：**无**项目侧栏。
- 项目切换器产品化：当前项目名 + 平台标签，禁止意义不明的「全部 / 12345」。
- `dev issue badge` 不得出现在正式产品 UI。

## 6. 项目头部

禁止每页重复长介绍段落。

Compact header 只显示：

- 项目名称
- 平台 · 行业（短标签）
- 当前阶段（人话）
- 编辑项目

长描述、原始需求 → 「项目资料」。

## 7. Workflow Header / Footer 标准

每个核心生产页：

1. `WorkflowBackNavV1`：← 上一步（语义返回，可刷新）
2. 弱化面包屑
3. 标题 + 一句话
4. 当前状态（人话）
5. 右上**最多一个** Primary
6. 底栏 `NextActionBarV1`：左上一步，右下一步
7. 同一 CTA 不得顶/中/底三处重复

`WorkflowBackNavV1` 已存在且回流验收通过：**实施时扩展覆盖，禁止平行造第二套返回逻辑。**
