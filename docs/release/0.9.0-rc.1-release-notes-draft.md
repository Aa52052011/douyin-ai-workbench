# 0.9.0-rc.1 Release Notes (Draft)

Release: **0.9.0-rc.1**
Type: **Web Release Candidate**
Date: 2026-09-17
Status: Draft — not tagged, not GA.

This is a candidate freeze of the local Web product loop. It is **not** production GA, not a Tauri installer, and not official Douyin publish.

## Highlights

- End-to-end **human-gated** loop: positioning → plan → script → video → accept → download → manual publish → register → manual metrics → AI review → ACCEPTED-only handoff → next plan.
- UI/UX Phase I and I.5 surface/color system frozen (9 browser routes PASS).
- PostgreSQL + Redis/BullMQ worker runtime verified locally (RC-01).
- Official Douyin OAuth/auto-publish and Tauri packaging remain out of scope.

## Included Features

Authentication, workspace/project, account positioning, content planning, script generation and confirmation, video generation and acceptance, download (start semantics), manual publication and registration, manual metrics, performance analysis, AI review, recommendation review, ACCEPTED-only feedback handoff, current-cycle and historical isolation, frozen UI, worker, Redis queue, PostgreSQL.

See `docs/release/rc-02-release-candidate-manifest.md` for the full matrix.

## Manual Human Gates

Every generation and cycle advance still requires operator confirmation. Rejected/deferred recommendations are not applied. Next-cycle plans are not auto-generated.

## Known Limitations

- Manual publication only; truth is USER_ASSERTED until official verification exists.
- No automatic Douyin metrics fetch; manual entry/import only.
- Download UI means DOWNLOAD_STARTED, not confirmed file-save completion.
- Desktop/tablet 1024+ baseline; phone UI not productized.
- Real creator assets improve video realism; landscape is not the primary Douyin path.

## Deferred Features

Official Douyin auto publish, automatic metrics fetch, platform-side verification.

## Not In This RC

Comment auto-reply, fully automated loop, mobile product, SaaS multi-tenant ops, billing, reseller edition, Tauri installer, code signing, auto updater, cloud DB/Redis, worker cluster.

## Runtime Requirements

- Node.js >= 20
- Next.js frontend on port **3010** (local RC)
- NestJS backend on port **3001** (`GET /health`)
- Worker process consuming BullMQ jobs

## Database Requirements

- PostgreSQL (local RC: `127.0.0.1:55432`, database `acf_dev`)
- Prisma migrations **CLEAN** (23 migrations including video final acceptance)
- Seed is **not** required for existing local RC data
- Do not commit dumps or `dump.rdb`

## Redis Requirement

Redis or Memurai at `127.0.0.1:6379` (`REDIS_URL`). Do not flush as part of release.

## FFmpeg Requirement

Required for real compose (`MEDIA_COMPOSE_PROVIDER=ffmpeg`) plus `ffprobe`. Optional mock compose is not a production compose path.
